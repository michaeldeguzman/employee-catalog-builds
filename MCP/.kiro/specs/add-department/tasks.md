# Implementation Plan
## Standing rules for every task
- Tasks run in order. None starts until the user approves this plan.
- **[CONFIRM]** marks a point where Kiro states the exact action and waits for the user's explicit yes. Every Mentor send and every publish is one. A yes for one send or one publish covers only that one.
- The prompts are the texts in design.md ("Prompt A", "Publish prompt A2", "Prompt B", "Publish prompt B2"), sent unchanged. Before sending, Kiro saves each one as its own file in `MCP/Prompts/` (006 to 009, names in design.md). If a prompt needs a change, Kiro stops and asks the user. It does not edit a prompt on its own.
- One Mentor session for tasks 2, 3, 5 and 6, with the app key debb6b49-7b59-ecf6-b2eb-50a5f78250f3 in the asset references. One turn at a time. Poll every run to terminal, then read the completion signals for the app before reporting.
- After every publish, Kiro runs the graph verification from design.md ("Verification after every publish") and reports every change outside the intended scope.
- Kiro works only on EmployeeCatalogMCP. It never touches EmployeeCatalogMW or any other app.
- ODC Studio is not opened in this change. There is no data check between the two prompts.
- Every new file goes in `MCP/`. SDD Base is read-only. Working files of this change go to `MCP/Reports/add-department/`.
- The reference graphs in `MCP/Reports/graphdiff/reference/` are for checking only. Nothing from them goes into a prompt.
- A fix prompt is an intervention: Kiro writes it with the real names, the user confirms the exact text before it is sent and again before the publish, and it is logged in `MCP/Reports/interventions.md`.
- There are no test-writing tasks in this plan.
