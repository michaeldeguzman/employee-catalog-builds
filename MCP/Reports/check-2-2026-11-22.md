### 1. BootstrapTimer

- Build A's `LoadSampleDataOnPublish` timer has the same four settings.

### 2. BootstrapData
- Three nodes: Start, one call to `BootstrapEmployee`, End. No If, no exception handler. Nothing can skip the call.

### 3. BootstrapEmployee
- Check: aggregate `GetEmployees` (source Employee, no filter) then If `GetEmployees.Count = 0` (operator Eq, Integer 0). True goes to the deserialize. False sets Message "skipped, N present" and ends.
- JSON literal: the graph keeps only the length and a SHA-1 prefix. Length 2466, prefix 2e83c0b72a. A compact JSON array built from spec.md section 10 (20 objects, keys `FirstName`, `LastName`, `JobTitle`, `Email`, `IsActive` in that order, `IsActive` as a JSON boolean, no `Id`) matches both exactly. The keys equal the Employee attribute names. Build A's literal has the same length and prefix.
- Deserialize: `DeserializeEmployees`, data type Employee List, date format ISO. Loop over `DeserializeEmployees.Data`. Each cycle calls `CreateEmployee` with Source `DeserializeEmployees.Data.Current` (type Employee), then returns to the loop. After the loop: Message "inserted N rows", End.
- Differences from build A's action: no exception handler (build A has AllExceptions, LogError true, AbortTransaction false) and the record is passed whole instead of field by field. Neither is a defect on its face. Known deviation D-1 applies: Message is an output, not a log line.

### 4. GetEmployees on Employee_List
- Fetch AtStart, MaxRecords 50, source Employee, sort LastName asc then FirstName asc.
- Filter 1: `Employee.IsActive`.
- Filter 2: `(SearchKeyword = "" Or Employee.FirstName Like ("%" + SearchKeyword + "%")) Or Employee.LastName Like ("%" + SearchKeyword + "%")`.
- The filters combine with AND. `SearchKeyword` is a Text local variable with no default, so it is "". The "%" and "" literals were confirmed by their SHA-1 prefixes.
- With an empty search and the 20 spec records, 3 are inactive (Hugo Brandt, Maya Petrov, Quinn Abara), so the query returns 17 rows, below the cap of 50.
- The table source is `GetEmployees.List`. "No employees found" shows only when `GetEmployees.IsDataFetched And GetEmployees.List.Empty`. The screen is consistent with an Employee table that has no active rows, not with a filter fault.
